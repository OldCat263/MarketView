# 日志排查报告

## 现象
`predict: false`，Rank 返回 0 items

## 日志分析
journalctl 显示：
- akshare `Please wait for a moment: X%|██▏| X/70` 进度条持续运行
- 说明 `_initial_load()` 仍在拉 spot 数据（akshare 有 tqdm 进度条，70 条/批）
- 无 `[Preload]` 或 `[batch/]` 输出
- 无 traceback 或 Exception

## 根因
**`_cache_lock` 长时间占用**

1. `_initial_load` 在 akshare 网络请求期间持有 `_cache_lock`
2. akshare 是同步阻塞的（非 async），拉完一个 batch 约 15-20s
3. `_precompute_predict` 和 `predict_batch` 都调用 `_cached_get` → 需要 `_cache_lock`
4. 锁被 `_initial_load` 占用 → 预计算和批量都等不到数据
5. Rank 返回空

## 修复方案
**解耦读写锁**：`_initial_load` 写缓存时释放锁给读者

```python
def _load_one(key, fn):
    try:
        # 先不拿锁，直接拉数据
        data = fn()
        # 拉完再拿锁写缓存
        with _cache_lock:
            # 现有的写入逻辑
            ...
    except:
        ...
```

## 影响范围
- 仅影响启动后 1-2 分钟的预测计算
- 对已有用户不影响（已经缓存的模块仍然可读）
- 重启后第一个请求的用户会等到预加载完成

## 优先级
P1 — 功能可用性问题，但非数据错误

**全球指数 K 线**：`inferCode('index', 'dji')` → `shdji` ❌

- ^IXIC → sh^IXIC → 空
- 000001 → sz000001 → ✅（腾讯不区分 sh/sz）
- 399001 → sz399001 → ✅
**根因**：V2.0.0 引入 `inferCode` 时没考虑全球指数是纯字母代码。
**新增 BUG11**。

**美股 K 线**：`inferCode('us', 'AAPL')` → `usAAPL` → 腾讯返回数据 ✅
美股问题不在前缀，在 spot 数据源（BUG8）。

### 修复方案
- BUG11：`inferCode` index 模块纯字母代码不加前缀
- BUG8：排查腾讯 US API，启用 akshare 备选

## 08:33 — BUG10 深入诊断：predict daemon stock 锁饥饿

### 现象
daemon 加了 45s 延迟 + 2 次重试后，stock predict 仍为 0 条。

### 深入诊断
```
服务器重启
├─ roller stock → akshare 拉 5527 只 → 占用 _cache_lock 每 3s（shard 写入）
├─ _initial_load → 也在跑 akshare 拉全量 → 5 分钟后还在 119/135
│
├─ T+45s  daemon 启动 → _get_codes_from_cache(stock)
│         → _cache_lock 被 roller 占 → 超时 → codes=[]
│         → 重试1(30s) → 还被占 → codes=[]
│         → 重试2(30s) → 还被占 → codes=[]
│         → 睡 300s...
│
├─ etf → 加载快 → daemon 读到 → ✅ 48 条
└─ hk  → 加载快 → daemon 读到 → ✅ 49 条
```

### 修复方案（BUG10）
daemon 用硬编码 top 50 热门股代码列表，不走 spot 缓存锁：
```python
_STOCK_POOL = ['000001','000002','000858','600519','601318',...]  # 50 只
```
零锁竞争，永远不空。
