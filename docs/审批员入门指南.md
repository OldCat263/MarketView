# MarketView 审批员入门指南

> **写给审批员**：本文档是**审批员 Onboarding 必读**，也是**复审 + 标级 + 改进意见模板索引**。
>
> 适用于：人类审批员 / AI Agent 审批员（如 Trae SOLO）
> 目标：**1.5 小时内能独立复审 + 标 P0/P1/P2 + 写改进意见**
> 项目当前状态：V2.2.0 数据源分离 · 已封版 ✅（stock/etf/index→东财 push2，预测只做 stock+etf）/ V2.2.2 预测加速 / V2.0.3 错峰+自选 / V2.0.2 磁盘缓存 / V2.0.1 智能预测加载加速 + MCP / V2.0.0 智能预测系统 / V1.9.0 P0 修复 / V1.8.6 秒开体验 / V1.8.0 新闻 / V1.7.0 K线

## 0. 同步更新铁律（最重要）

> **每次复审后必须按以下顺序回报/更新**：
>
> | 步骤 | 操作 | 责任人 | 时效 |
> |------|------|--------|------|
> | 1 | 接收执行者回报（已由设计师转发） | 审批员 | 收到后 **24h 内**出意见 |
> | 2 | 按 [§6 复审清单](#6-复审清单模板) 跑一遍 | 审批员 | — |
> | 3 | 按 [§7 P0/P1/P2 标准](#7-p0p1p2-判定标准) 标级 | 审批员 | — |
> | 4 | 按 [§9 改进意见模板](#9-改进意见模板) 出意见 | 审批员 | — |
> | 5 | 发回设计师（不是发给执行者！） | 审批员 | — |
> | 6 | 设计师改 CLAUDE.md + 设计师入门指南 | 设计师 | 收到意见后 **24h 内**改完 |
>
> **不标级 = 流程违规**。详见 [开发手册 §十](./开发手册.md)。

### 0.1 你的边界（必背）

| 你做 | 你**不**做 |
|------|------------|
| ✅ 复审代码改动 | ❌ 改 CLAUDE.md |
| ✅ 标 P0/P1/P2 | ❌ 改需求边界 |
| ✅ 写改进意见 | ❌ 直接指挥执行者改 |
| ✅ 验证技术文档一致性 | ❌ 维护文档（设计师的事）|
| ✅ 跑实测验收命令 | ❌ 跳过设计师直接决定封版 |

> **你的产出 = 标级 + 改进意见**。**你的话语权 = 拒绝签字封版**。设计师必须尊重你的 P0 标记。

## 1. 角色定位

| 角色 | 职责 | 工具 |
|------|------|------|
| 设计师 | 出需求 + 设计 + 维护文档 + 审批技术文档 | [设计师入门指南](./设计师入门指南.md) |
| 用户（产品） | 提需求 + 转发指令 | 微信/钉钉 |
| 执行者 | 写代码 + 同步技术文档 + 回报 | [执行者入门指南](./执行者入门指南.md) |
| **审批员（你）** | **复审 + 标级 + 改进意见** | **本指南** |

**你不写代码、不改文档**，但要：
- 看得懂 diff（能定位到行号、识别改动意图）
- 标得准级别（P0/P1/P2 不混淆）
- 写得清意见（具体可执行，不是空话）
- 顶得住压力（P0 不放过，设计师不能压你）

> **术语对齐**：**标级 = 标 P0/P1/P2 = 给问题分级**。本指南统一用"标级"，与设计师/执行者指南的"标 P0/P1/P2"等价。

## 4. 铁律（复审核心）

| # | 铁律 | 复审动作 |
|---|------|----------|
| 1 | **核心文件不变** | `git diff --stat backend/main.py frontend/js/core.js` 必须是空或仅设计稿列出的改动 |
| 2 | **先改 CLAUDE.md 再写代码** | 回报里"CLAUDE.md 已含本次改动方案"必须 ✅ |
| 3 | **服务端缓存允许，数据源必须公开 API** | 缓存可用但数据必须来自免费公开 API，`grep -rn "open(\|write(\|dump(" backend/` 不应有本地文件主数据源 |
| 4 | **数据源仅限免费公开 API** | 新数据源必须在免费清单（腾讯/东财/新浪/Binance/AkShare）|
| 5 | **做完记录版本历史** | 回报里 commit message 符合 `<hash> V<x.y.z>: ...` 格式 |
| 6 | **每个模块完全独立封装** | diff 只触及本模块文件，不跨模块 |
| 7 | **改代码必同步技术文档** | 回报里"技术文档同步"必须列出对应文件（与设计稿"技术文档改动范围"对齐）|
| 8 | **设计师必审批技术文档** | 设计师已签字（回报里有设计师审批栏）|

> 来源：[CLAUDE.md 铁律](../CLAUDE.md) + [执行者入门指南 §0.1](./执行者入门指南.md)。**每条都对应一个具体的 P0/P1 判定**（见 §7）。

## 5. 协作流程（你在哪一步）

```
1. 用户提需求
2. 设计师：出设计稿 + 更新文档
3. 设计师：出实施指令
4. 用户：转发执行者
5. 执行者：实施 + 同步技术文档
6. 执行者：按 §7 模板回报 → 发给设计师
7. 设计师：3 项验收（代码 + 技术文档 + 标级）
8. ⭐ 你：复审设计师的验收 + 标级 + 出改进意见
   8.1 跑 §6 复审清单（10 项 + 4/5 类实测）
   8.2 按 §7 重标级（可与设计师不同，P0 不放过）
   8.3 按 §9 出改进意见
9. 发回设计师
10. 设计师：审批通过 → CLAUDE.md 加版本号 → 封版
```

> 详细见 [开发手册 §十](./开发手册.md)。

### 5.1 5 步分开发的复审策略
当设计师出"5 步分开发"指令（如 V1.7.0）时，你**只在 Step 5 介入**：
- Step 1~4：设计师轻量验收，不经过你
- Step 5：设计师验收后转你完整复审

> 5 步中只 1 次完整复审，避免 5×3=15 次拖进度；Step 5 必走完整（接口/UI/SSE 联调 P0 高发）。

### 5.2 失败回滚
复审 P0 打回无法快速修复时：设计师 `git revert <hash>` → 回滚到上一版本 → 重新走流程。

### 你与设计师意见不一致时

| 场景 | 你的动作 |
|------|----------|
| 你标 P0，设计师说 P1 | 在 §9 意见里写"复审升级 P0 + 理由"，设计师必须重审 |
| 你标通过，设计师标 P1 | 接受设计师标级（他更懂设计意图）|
| 你发现设计稿本身有问题 | 在 §9 写"设计稿问题：..."，由设计师决定改设计稿 |

> **核心原则**：标级以你为准（P0 不放过），设计边界以设计师为准。

## 7. P0/P1/P2 判定标准

### P0（致命：必须修复，否则拒收）

| 类型 | 例子 | 触发 |
|------|------|------|
| 数据正确性 | 数据计算错误、字段名错位、fallback 失效 | 实测命令返回错值 |
| 铁律违反 | 核心文件被改 / 本地存储 / 收费 API | grep 命中 |
| 模块破坏 | 改一个模块影响其他模块 | 切模块异常 |
| 实时性 | SSE 断、心跳停、viewTime 卡死 | F12 看到 `shard:-1` 不再推 |
| 设计稿脱节 | 执行者擅自扩边界（新增功能/字段未在设计稿）| diff 与设计稿不一致 |
| 文档未同步 | 改了代码但技术文档完全没动 | 回报里"技术文档同步"为空 |

> **P0 = 设计师也不能否决**。必须修复后重新走流程。

### P1（重要：必须修复，可下次版本）

| 类型 | 例子 |
|------|------|
| 字段不一致 | API 文档字段名与代码 response 不一致（不影响功能）|
| 注释不更新 | fetcher 头部注释没反映新数据源 |
| 错误日志缺失 | 关键失败路径没有 print 留上下文 |
| 测试覆盖不足 | 新功能没有 curl 验收命令 |
| 性能退化 | 数据量没变但加载时间 +50% |

### P2（建议：可后续优化）

| 类型 | 例子 |
|------|------|
| 代码风格 | 命名不一致、注释格式不统一 |
| 文档措辞 | API 描述不清楚、故障排查不完整 |
| 边界场景 | 未处理空数据、特殊字符、超长字符串 |
| 移动端 | 某模块在手机模式显示异常 |

### 通过标准

**所有 10 项复审清单 + 4 类实测命令全过 + 无 P0/P1** = 通过

> **任一 P0 = 整体不通过**，必须打回。

## 8. 复审常见坑

| 坑 | 怎么识别 |
|----|----------|
| 假装跑过验收 | 回报里"实际输出"是空白或抄设计稿 |
| 只贴 diff 不实测 | 没有 curl / F12 截图 |
| 文档"改过"但内容没变 | git log 看 commit 实际改动 |
| 设计师未审批就送来 | 回报里没有"技术文档同步 4 检查点"全过 |
| 边界悄悄扩了 | diff 与设计稿的"技术文档改动范围"勾选不一致 |
| 测试数据是 mock | 跑你实测命令看真实数据 |
