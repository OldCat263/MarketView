## 一、项目哲学（Why）

### 核心目标
**一站式展示全球金融市场实时数据，给客户用。**

### 设计原则（按优先级）

| # | 原则 | 含义 |
|---|------|------|
| 1 | **实时优先** | 用户看到的数据必须 ≤ 5s 前 |
| 2 | **零本地存储** | 服务端不写盘，客户端不存数据（仅 UI 状态用 sessionStorage）|
| 3 | **免费公开 API** | 不用收费 API、API Key、Token |
| 4 | **模块独立** | 6 个金融模块互不依赖，新增模块零侵入 |
| 5 | **文档先行** | CLAUDE.md 必先于代码更新 |
| 6 | **可回滚** | 每次发布一个 commit，出问题能秒回滚 |

## 二、铁律（不可违反）

| # | 铁律 | 违反后果 |
|---|------|----------|
| 1 | **核心文件不变**，不许随意加文件 | 架构腐化 |
| 2 | **先改 CLAUDE.md 再写代码** | 文档与代码脱节 |
| 3 | **零本地存储** | 部署复杂、跨节点不一致 |
| 4 | **数据源仅限免费公开 API** | 商业风险、运营成本 |
| 5 | **做完记录版本历史** | 无法回溯 |
| 6 | **每个模块完全独立封装** | 改一个崩全部 |

### 铁律的边界判定

| 场景 | 判定 |
|------|------|
| 新增 `backend/fetcher/xxx.py` | ✅ 允许（fetcher 目录内独立文件） |
| 新增 `frontend/js/modules/xxx.js` | ✅ 允许（modules 目录内独立文件） |
| 新增 `docs/xxx.md` | ✅ 允许（docs 目录） |
| 新增 `backend/yyy.py` | ❌ 禁止（核心目录外） |
| 新增 `frontend/lib/zzz.js` | ❌ 禁止（核心目录外） |
| 加 `pandas` 依赖 | ⚠️ 需设计者审批（引入重依赖） |
| 写 `open('foo.json', 'w')` | ❌ 禁止（铁律 3） |

## 三、技术栈

### Backend
| 组件 | 选型 | 理由 |
|------|------|------|
| Web 框架 | **FastAPI** | 异步原生，SSE 支持好 |
| ASGI | **uvicorn** | 标准 ASGI 服务器 |
| HTTP 客户端 | **httpx**（异步）+ **requests**（同步） | 兼顾两种场景 |
| 数据源 | **AkShare** + 腾讯 + Binance + 新浪 | 免费、稳定、中文 |
| 缓存 | **内存 dict**（`_cache`） | 零本地存储 |
| 进程模型 | **workers=1** | SSE 长连接 + 免费 API 限流 |

### Frontend
| 组件 | 选型 | 理由 |
|------|------|------|
| 框架 | **原生 JS**（无 React/Vue） | 减少依赖、可控 |
| UI 库 | **CSS 手写** | 暗色主题可控 |
| 图表 | **ECharts 5**（V1.7.0+） | K线图标准 |
| 实时通信 | **EventSource（SSE）** | 服务器推送标准 |
| 客户端缓存 | **sessionStorage** | 仅 UI 状态恢复 |

### 第三方 CDN
- ECharts: `https://cdn.jsdelivr.net/npm/echarts@5.4.3/dist/echarts.min.js`
- 不引其他 CDN（保持零外部依赖原则）

## 五、模块注册模式（铁律 6 的具体实现）

### Backend 模式

每个模块在 `backend/fetcher/` 下**独立一个文件**，提供：
- 一个拉全量的函数（`get_xxx_json()`）
- 一个分片拉取函数（`fetch_xxx_shard(i, n)`）—— V1.6.0 起

```python
# backend/fetcher/etf.py 示例
def get_etf_json():
    """拉全量"""
    return json.dumps(rows, ensure_ascii=False)

def fetch_etf_shard(shard_id, total_shards):
    """分片拉取（V1.6.0+）"""
    all_data = get_etf_data()
    chunk = len(all_data) // total_shards
    start = shard_id * chunk
    end = start + chunk if shard_id < total_shards - 1 else len(all_data)
    return all_data[start:end]
```

### Frontend 模式

每个模块在 `frontend/js/modules/` 下**独立一个文件**，通过 `MV.register()` 注册：

```js
// frontend/js/modules/etf.js 示例
MV.register({
  id: 'etf',
  name: 'ETF',
  icon: '📊',
  endpoint: '/api/etf/spot',
  columns: ['代码', '名称', '最新价', '涨跌幅', ...],
  sortCol: '涨跌幅',
  postProcess: (rows) => rows,
  parseResponse: (resp) => resp.data
});
```

### 模块状态隔离

每个模块在 `core.js` 的 `ST` 对象下独立保存：

```js
ST = {
  stock: { rows, cols, page, sortKey, sortDir, updateTime, fetchTime, search },
  etf:   { ... },
  hk:    { ... },
  ...
}
```

**ST[module] 重建时必须保留 `fetchTime`**，否则 liveStatus 变红（V1.6.0.5 教训）。

## 六、数据流

```
┌──────────┐    ┌────────────┐    ┌──────────┐    ┌────────┐
│ 数据源   │ →  │ fetcher/*  │ →  │ _cache   │ →  │ /api/  │
│ (免费API)│    │ (纯函数)   │    │ (分片内存)│    │ xxx/   │
└──────────┘    └────────────┘    └──────────┘    │ spot   │
                                                   └────┬───┘
                                                        │
                   ┌────────────┐    ┌──────────┐        │
                   │ EventSource│ ←  │ SSE 队列 │ ←──────┘
                   │ (浏览器)   │    │ (per-mod)│
                   └─────┬──────┘    └──────────┘
                         ↓
                   ┌──────────┐
                   │ ST[mod]  │ → render() → DOM
                   └──────────┘
```

### 关键点
- **数据源是真相**，fetcher 是翻译，cache 是缓冲
- **SSE 不重传**，断了客户端用 `EventSource` 自动重连
- **分片滚动**：N 个分片每 interval 秒轮转一个，稳态全量覆盖

## 七、实时性策略

### V1.6.0 起的三层保障

| 层级 | 机制 | 作用 |
|------|------|------|
| 1 | **分片滚动刷新** | 数据本身持续更新 |
| 2 | **SSE 增量推送** | 浏览器侧实时看到 |
| 3 | **3s 心跳**（V1.6.0.6） | 维持连接活性显示 |

### SSE 消息格式

```js
// 真实数据推送
{shard: 0, data: [...], ts: 1234567890.123}

// 心跳（V1.6.0.6+）
{shard: -1, data: [], ts: 1234567893.456}
```

### 客户端 viewTime vs liveStatus（V1.6.0.8 回滚）

| 指标 | 含义 | 更新时机 |
|------|------|----------|
| **viewTime** | 客户端实时时间（V1.6.0.8 回滚到 V1.6.0.3 行为）| `setInterval(refreshStamp, 1000)` 每秒跳 |
| **liveStatus** | SSE 数据新鲜度 | 心跳或数据推送时刷新 fetchTime（绿/红）；SSE 断连时显式"离线"（V1.6.0.8 加）|

**两个指标解耦**：
- 绿点 + 跳秒时间 = 行情正常推送
- 红点 + 跳秒时间 = SSE 断连（显式"离线"）

## 八、缓存策略

### 服务端（`_cache`）

```python
_cache = {
  'stock': {
    'shards': {
      0: {'data': [...], 'ts': 1234567890.0},
      1: {'data': [...], 'ts': 1234567891.0},
      ...
    },
    'cols': [...]
  },
  ...
}
```

**schema 铁律**：写入 `'shards'` 键，读取也走 `'shards'` 键。**不允许**用 `'data'` 键（V1.6.0.1 教训）。

### 客户端（sessionStorage）

```js
mv_stock = {"data": [...], "ts": 1234567890000}  // TTL 15s
```

**作用**：仅 UI 状态恢复（切模块、刷新页面），**不作为数据源**。
**TTL**：`Date.now() - d.ts < 15000` 过期则重拉。

### K线（sessionStorage，V1.7.0+）

K线数据量大（每请求 750 根），每次切周期/切模块都重拉浪费带宽。采用独立缓存策略：

```js
// key: kl_{module}_{code}_{period}
// value: {data: {...}, ts: <timestamp>}
```

**TTL 策略**：交易时段 60s（避免错过最新 K线），非交易时段无限（历史数据不变）。
**实现**：`MV.cacheGet(key, noTtl)` — 第二个参数 `noTtl=true` 跳过 15s TTL 检查。

> 与 spot 数据不同：spot 走 SSE 实时推送无需客户端缓存 TTL 很长；K线无 SSE（Step 5 计划中），靠缓存减少 API 调用。

```
7. 设计者：3 项验收

8. ⭐ 审批员：复审设计师的验收（见 [审批员入门指南 §6](./审批员入门指南.md)）

```

### 5 步分开发的审批策略
当一个版本分 5 步开发（如 V1.7.0）时，按"轻量验收 + 完整复审"分层：
| 阶段 | 流程 | 责任 |
|------|------|------|
| Step 1~4 | 走"实施 → 回报 → 设计师轻量验收"（不经过审批员）| 设计师重点审"模块独立 + 文档同步"（P0 高发区）|
| Step 5 | 走"实施 → 回报 → 设计师验收 → 审批员完整复审 → 封版" | 全员（接口/UI/SSE 完整联调）|

> **理由**：避免 5×3=15 次完整流程拖进度；Step 5 必走完整（P0 高发）。
> **风险**：Step 1~4 漏掉的 P0 要 Step 5 才能发现。
> **应对**：Step 1~4 设计师重点审"模块独立 + 文档同步"两个 P0 高发区。

### 复审不通过的责任划分
审批员打回后，**谁**来改？
| 问题类型 | 责任人 |
|----------|--------|
| 代码 / 技术文档 | 设计师转发执行者 |
| 设计稿 / 流程 / 边界 | 设计师自己改 |
| 设计师入门指南 / 开发手册 | 设计师自己改 |

### 失败回滚
复审 P0 打回无法快速修复时：`git revert <commit-hash>` → 回滚到上一版本 → 重新走流程。

## 十一、版本管理

### 命名规则

```
V<major>.<minor>.<patch>
```

- **major**：架构变更（如 V2.0.0 重写后端）
- **minor**：新功能（如 V1.7.0 K线图）
- **patch**：bug 修复 + 微调（如 V1.6.0.1 ~ V1.6.0.6）

### 版本历史位置

- 主索引：`CLAUDE.md` 版本历史表
- 单版本细节：已封版的版本**不另存**设计稿（避免文档膨胀）
- 未封版的设计：可临时建 `docs/Vx.y.z-设计稿.md`，封版后删除

### Commit 规范

```
<hash> V<version>: <一句话总结>
```

例：`19063fc V1.6.0.6: heartbeat push + viewTime data-driven`

## 十三、常见陷阱（教训沉淀）

| 陷阱 | 教训 | 版本 |
|------|------|------|
| 缓存 schema 不统一（写 `data` 读 `shards`）| 写入和读取必须用同一套 schema | V1.6.0.1 |
| 美股代码缺 `us` 前缀 → 腾讯返空 | 腾讯美股 API 需 `usAAPL` 格式 | V1.6.0 |
| HK 单一源不稳 → 0 行 | 港股必须多源 fallback | V1.6.0.1 |
| `except: pass` 吞错 | 必须 `print` 留调试上下文 | V1.6.0.1 |
| viewTime 嵌套在 `if(changed)` → 卡死 | viewTime 必须独立 `setInterval` | V1.6.0.3 |
