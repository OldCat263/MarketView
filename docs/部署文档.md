# MarketView 部署文档

> **写给后来者**：本文档记录 MarketView 在 `oldcat.site` 的生产部署配置。
> 包括 Nginx、systemd、SSL、环境变量、回滚流程。
> 下次服务器迁移/扩容/排障前必读。

---

## 一、部署架构

```
┌──────────┐    HTTPS    ┌──────────┐   HTTP    ┌──────────┐    ┌──────────┐
│ 浏览器   │ ────443───→ │  Nginx   │ ──8001──→ │ Uvicorn  │ ──→ │ FastAPI  │
│ (用户)   │              │ (反代)   │           │ (ASGI)   │     │ (后端)   │
└──────────┘              └──────────┘           └──────────┘     └─────┬────┘
                                                                      │
                                                                  ┌───┴────┐
                                                                  │ 数据源  │
                                                                  │ 免费API │
                                                                  └────────┘
```

| 组件 | 角色 | 关键参数 |
|------|------|----------|
| Nginx | HTTPS 反代 + 静态文件 + SSE 优化 | 443 / 8001 反代 |
| Uvicorn | ASGI 服务器 | 0.0.0.0:8001 / workers=1 |
| FastAPI | 应用框架 | lifespan 启动 roller + 心跳 |
| Let's Encrypt | SSL 证书 | 90 天自动续期 |
| systemd | 进程管理 | 自动重启 / 开机启动 |

## 三、Nginx 配置

### 3.1 站点配置 `/etc/nginx/sites-available/marketview`

```nginx
# HTTP → HTTPS 重定向
server {
    listen 80;
    server_name oldcat.site;
    return 301 https://$server_name$request_uri;
}

# HTTPS 主站
server {
    listen 443 ssl http2;
    server_name oldcat.site;

    # SSL 证书（Let's Encrypt）
    ssl_certificate /etc/letsencrypt/live/oldcat.site/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/oldcat.site/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # 静态文件（前端）
    root /opt/marketview/frontend;
    index index.html;

    # SSE 关键配置（V1.6.0+ 必须）
    # 1. 禁用缓冲：数据立即推到客户端
    # 2. 长超时：SSE 连接可能持续数小时
    # 3. 禁用 gzip：避免 SSE 流被压缩
    proxy_buffering off;
    proxy_cache off;
    proxy_set_header Connection '';
    proxy_http_version 1.1;
    proxy_read_timeout 86400s;
    proxy_send_timeout 86400s;

    # 后端 API + SSE
    location /api/ {
        proxy_pass http://127.0.0.1:8001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 前端静态文件
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

### 3.2 启用站点

```bash
sudo ln -s /etc/nginx/sites-available/marketview /etc/nginx/sites-enabled/
sudo nginx -t                          # 验证配置
sudo systemctl reload nginx
```

### 3.3 SSE 配置错误的后果

| 错误 | 症状 |
|------|------|
| 忘加 `proxy_buffering off` | 客户端看到 5~10s 延迟 |
| `proxy_read_timeout` 太短 | SSE 连接 60s 后断开 |
| 启用了 `gzip` | SSE 流被破坏，前端 JSON 解析失败 |

## 四、systemd 服务单元

### 4.1 `/etc/systemd/system/marketview.service`

```ini
[Unit]
Description=MarketView FastAPI Backend
After=network.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/opt/marketview/backend

# V1.6.0 起必须 workers=1（铁律）
# 原因：SSE 长连接 + 免费 API 限流
ExecStart=/opt/marketview/venv/bin/uvicorn main:app --host 0.0.0.0 --port 8001 --workers 1

# 环境变量
Environment=CRYPTO_PROXY=http://127.0.0.1:7897
Environment=PYTHONUNBUFFERED=1
# V2.0.3 错峰启动开关（如需禁用可设 START_DELAY=0）
# Environment=START_DELAY=1

# 重启策略
Restart=always
RestartSec=5

# 日志
StandardOutput=journal
StandardError=journal
SyslogIdentifier=marketview

# 资源限制
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

### 4.1.1 V2.0.2+ 磁盘缓存目录权限

V2.0.2 引入 `backend/.cache/` 持久化，必须给 `www-data` 写权限：

```bash
# 一次性设置
sudo mkdir -p /opt/marketview/backend/.cache
sudo chown -R www-data:www-data /opt/marketview/backend/.cache
sudo chmod 755 /opt/marketview/backend/.cache

# 验证（应用启动后会自动写）
ls -la /opt/marketview/backend/.cache/
# 预期：spot_cache.json + kline_cache.json + watchlist.json（V2.0.3+）
```

**⚠️ 常见问题**：.cache 目录没写权限 → 启动 30s 后报 `PermissionError` 但不退出，磁盘缓存失效。

**systemd 加 ReadWritePaths**（systemd v244+ 推荐写法）：
```ini
ReadWritePaths=/opt/marketview/backend/.cache
```

### 4.1.2 V2.0.3 错峰启动（默认开启）

main.py lifespan 内置 `START_DELAY=1` 开关，错峰间隔 0/5/10/15/20/45s 启动 rollers：

| 模块 | start_delay | 完整轮转 |
|------|-------------|----------|
| 加密 + A股 + 新闻 | 0s | 5/40/60s |
| ETF | 5s | 25s |
| 港股 | 10s | 30s |
| 美股 | 15s | 15s |
| 指数 | 20s | 5s |
| 预测 | 45s | 5min |

**禁用错峰**（不推荐）：`Environment=START_DELAY=0` 即可。

### 4.1.3 V1.8.6 首屏快照写权限

`frontend/snapshot.json` 启动 5s 后由后端写出，必须给 `www-data` 写 frontend 目录权限：

```bash
sudo chown -R www-data:www-data /opt/marketview/frontend
sudo chmod 755 /opt/marketview/frontend
```

**故障排查**：前端打开 1s 后还是空白 → `ls -la /opt/marketview/frontend/snapshot.json` 是否存在？不存在说明写权限问题。

### 4.2 启用服务

```bash
sudo systemctl daemon-reload
sudo systemctl enable marketview
sudo systemctl start marketview
sudo systemctl status marketview
```

### 4.3 常用命令

```bash

sudo systemctl status marketview

# 实时日志
sudo journalctl -u marketview -f

# 重启
sudo systemctl restart marketview

# 停止
```

## 六、环境变量

| 变量 | 必须 | 默认 | 说明 |
|------|------|------|------|
| `CRYPTO_PROXY` | 否 | 无 | 加密货币数据源代理（如 `http://127.0.0.1:7897`）。无则 crypto 模块不可用 |
| `PYTHONUNBUFFERED` | 否 | 0 | 设为 1 让 Python 日志立即输出到 journal |

### 6.1 设置环境变量

**方式 A：systemd 单元**（推荐）
```ini
Environment=CRYPTO_PROXY=http://127.0.0.1:7897
```

**方式 B：环境文件**
```bash
sudo nano /opt/marketview/.env
# 内容：
# CRYPTO_PROXY=http://127.0.0.1:7897
```
然后在 systemd 单元中加：
```ini
EnvironmentFile=/opt/marketview/.env
```

## 七、部署流程

### 7.1 首次部署

```bash
# 1. 克隆代码
sudo mkdir -p /opt/marketview
sudo chown $USER:$USER /opt/marketview
git clone <repo> /opt/marketview

# 2. 创建虚拟环境
cd /opt/marketview/backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 3. 配置 Nginx
sudo cp deploy/nginx/marketview /etc/nginx/sites-available/
sudo ln -s /etc/nginx/sites-available/marketview /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# 4. 配置 systemd
sudo cp deploy/systemd/marketview.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now marketview

# 5. 申请 SSL
sudo certbot --nginx -d oldcat.site
```

### 7.2 更新部署

```bash
cd /opt/marketview
git pull

# 后端更新
cd backend
source venv/bin/activate
pip install -r requirements.txt    # 仅当 requirements.txt 变更
sudo systemctl restart marketview

# 前端更新（无需重启后端）
# 静态文件直接覆盖即可
sudo cp -r frontend/* /opt/marketview/frontend/
```

### 7.3 回滚

```bash
cd /opt/marketview
git log --oneline -10           # 查看历史
git checkout <commit-hash>      # 回滚到指定版本
sudo systemctl restart marketview
```

## 九、常见部署问题

### 9.1 端口冲突

**症状**：`bind: address already in use`
**诊断**：`sudo lsof -i :8001`
**解决**：杀掉占用进程或改端口

### 9.2 SSE 断连

**症状**：浏览器 1~2 分钟断一次
**诊断**：检查 Nginx 配置
- 缺 `proxy_buffering off`？
- `proxy_read_timeout` 太短？
**解决**：补配置 + `sudo nginx -s reload`

### 9.3 workers > 1 导致 SSE 断

**症状**：SSE 连接立即断开或 404
**根因**：V1.6.0 起强制 `--workers 1`（铁律）
**解决**：改 systemd 单元 `--workers 1`

### 9.4 CRYPTO_PROXY 未生效

**症状**：crypto 模块显示"未检测代理"
**诊断**：`sudo systemctl show marketview | grep CRYPTO`
**解决**：改 systemd 单元 + `systemctl daemon-reload` + `restart`

### 9.5 静态文件 404

**症状**：浏览器打开 `https://oldcat.site` 看到 Nginx 默认页
**根因**：Nginx `root` 路径错误
**解决**：检查 `/etc/nginx/sites-available/marketview` 的 `root` 指向 `/opt/marketview/frontend`

### 9.6 V2.0.2 磁盘缓存 PermissionError（V2.0.2+）

**症状**：journal 日志出现 `PermissionError: [Errno 13] Permission denied: '.cache/spot_cache.json.tmp'`
**根因**：`www-data` 用户没 `.cache/` 写权限
**诊断**：
```bash
ls -la /opt/marketview/backend/.cache/
# 所有者应是 www-data
```
**解决**：
```bash
sudo chown -R www-data:www-data /opt/marketview/backend/.cache
sudo systemctl restart marketview
```

### 9.7 V1.8.6 首屏快照没生成（V1.8.6+）

**症状**：浏览器打开 1s 后还是空白，Network 看不到 `snapshot.json`
**根因**：`www-data` 没 `frontend/` 写权限，lifespan 启动 5s 后写 snapshot.json 失败被静默吞掉
**诊断**：
```bash
ls -la /opt/marketview/frontend/snapshot.json  # 不存在 = 写失败
sudo journalctl -u marketview --since "1 min ago" | grep snapshot
```
**解决**：
```bash
sudo chown -R www-data:www-data /opt/marketview/frontend
sudo chmod 755 /opt/marketview/frontend
sudo systemctl restart marketview
```

### 9.8 V2.0.3 错峰启动导致启动慢（V2.0.3+）

**症状**：从 `systemctl start` 到全部模块 ready 要 30~50s（之前 5s）
**根因**：故意错峰，避开冷启动挤数据源
**诊断**：journal 看到 `daemon started: predict` 在 45s 之后
**解决**（如不想要错峰）：systemd 单元加 `Environment=START_DELAY=0` + restart
