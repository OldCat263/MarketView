# MarketView 故障排查手册

> **写给后来者**：本文档沉淀 MarketView 项目历次故障的诊断与修复方法。
> 按"症状 → 诊断 → 解决"组织，**复制命令即可用**。
> 每次新坑修复后，**必须**追加到本文档（铁律 5 延伸）。

## 0. 通用调试工具

```bash
# 后端日志（实时）
sudo journalctl -u marketview -f

# 后端日志（最近 100 行）
sudo journalctl -u marketview -n 100

# 后端健康检查
curl -s https://oldcat.site/api/health

# SSE 心跳测试
curl -N -m 6 https://oldcat.site/api/stream/stock | grep -c shard.-1
# 预期 1~2（6s 内 3s 一次）

# API 数据量
curl -s https://oldcat.site/api/etf/spot | python -c "import sys,json; print(len(json.load(sys.stdin)['data']),'ETF')"

# 浏览器侧：F12 → Network → EventStream → 应持续看到 data: 行
```

## 1. 实时性问题

### 1.1 浏览器 1~2 分钟断一次 SSE

**症状**：EventStream 自动重连，绿点闪
**根因**：Nginx 缓冲或超时
**诊断**：
```bash
sudo nginx -T 2>/dev/null | grep -A 2 "location /api/"
# 查 proxy_buffering 和 proxy_read_timeout
```
**解决**：补配置
```nginx
location /api/ {
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 86400s;
    proxy_send_timeout 86400s;
}
sudo nginx -t && sudo nginx -s reload
```

### 1.2 liveStatus 显示"19秒前"红点

**症状**：数据没变化时，绿点变红，显示秒数
**根因**：V1.6.0.6 之前后端不推空分片，前端 fetchTime 不更新
**解决**：
- 后端 main.py 有 `_heartbeat` 函数（每 3s 推 `shard:-1`）
- 前端 core.js `_sse.onmessage` 开头有 `if (msg.shard === -1)` 分支
- 缺一不可

**检查命令**：
```bash
grep -n "shard.*-1" backend/main.py        # 应有心跳
grep -n "shard === -1" frontend/js/core.js # 应有前端分支
```

### 1.3 viewTime 不更新

**症状**：表头时间停在一个值不动
**根因**（任一）：
- V1.6.0.3 之前：viewTime 嵌套在 `if(changed)` 内
- V1.6.0.4 之前：viewTime 嵌套在 `if (s && s.fetchTime)` 内
- V1.6.0.13 之前：viewTime 嵌套在 `if(tab)` 内（首页 / 切模块瞬间 `tab=''` 时不跳）
- V1.6.0.15 之前：openModule 手动设 viewTime 为 `ST[m].fetchTime`（数据时间，切模块瞬间显示老时间）
**解决**：
- viewTime 应在 SSE onmessage 内、**仅在真实数据分支**更新
- 不依赖 fetchTime 状态

**验证**：
```bash
grep -A 3 "viewTime" frontend/js/core.js
# 应看到：vt.textContent = '更新 ' + new Date().toLocaleTimeString()
# 不应有：if (s && s.fetchTime) { ... vt.textContent ... }
```

### 1.4 切模块后 liveStatus 立即变红

**症状**：切换模块，绿点瞬间变 "--"
**根因**：ST 重建时漏 `fetchTime`（V1.6.0.5 之前）
**解决**：3 处 ST 重建必须带 `fetchTime`
```js
ST[tab] = { rows, cols, page, sortKey, sortDir, updateTime, fetchTime: ST[tab]?.fetchTime || Date.now(), search: ... }
```

**验证**：
```bash
grep -c "fetchTime: ST\[tab\]" frontend/js/core.js
# 应 ≥ 3（doSort / openModule / goPage）
```

## 2. 数据问题

### 2.1 某模块显示 0 条

**症状**：表格空，"0 条"
**根因**（按概率）：
1. 数据源限流（免费 API 常见）
2. fetcher 报错但被吞
3. SSE 分片还没刷到

**诊断**：
```bash
# 1. 看后端日志
sudo journalctl -u marketview -n 200 | grep -i "error\|shard.*err"

# 2. 直接调 API
curl -s https://oldcat.site/api/etf/spot | python -c "import sys,json; d=json.load(sys.stdin); print('rows:', len(d.get('data',[])))"

# 3. 等 1 分钟看 roller 是否补数据
```

**解决**：
- 等 1~2 分钟（限流恢复）
- 看后端日志具体错误
- 必要时手动重启 `sudo systemctl restart marketview`

### 2.2 关键字段为空

**症状**：表格有行，但价格/涨跌幅都是 "-"
**根因**：
- V1.6.0 之前：A股缺"振幅/换手率/量比"
- 美股字段名不匹配（东财 vs 腾讯）
- fetcher 解析逻辑漏字段

**诊断**：
```bash
curl -s https://oldcat.site/api/stock/spot | python -c "
import sys, json
d = json.load(sys.stdin)['data']
if d:
    print('cols:', list(d[0].keys()))
    print('row0:', d[0])
"
```

**解决**：
- A股：用腾讯源（V1.6.0 强制）
- 美股：腾讯源 + us 前缀（V1.6.0）
- 字段名匹配见 `docs/API文档.md`

### 2.3 涨跌幅全部 0

**症状**：所有股票涨跌幅 0%
**根因**：
- 数据源问题（昨收=今开）
- 解析错误（字符串未转 float）

**诊断**：
```bash
curl -s https://oldcat.site/api/stock/spot | python -c "
import sys, json
d = json.load(sys.stdin)['data']
for r in d[:3]:
    print(r.get('代码'), r.get('最新价'), r.get('昨收'), r.get('涨跌幅'))
"
```

**解决**：看后端日志的 fetcher 报错

## 3. 启动问题

### 3.1 启动崩溃

**症状**：`systemctl status marketview` 显示 failed
**诊断**：
```bash
sudo journalctl -u marketview -n 50 --no-pager
```
**常见根因**：
- Python 虚拟环境路径错
- 依赖未装（`pip install -r requirements.txt`）
- fetcher 导入错误（V1.6.0.1 修复过）
- 端口被占

### 3.2 lifespan 启动卡住

**症状**：服务启动但 SSE 路由不工作
**根因**（V1.6.0.1 之前）：lifespan 启动阻塞（如 crypto 代理扫描）
**解决**：lifespan 内所有重操作改为 fire-and-forget
```python
import asyncio as _aio
_aio.ensure_future(crypto_status())  # 不 await
```

### 3.3 美股首次 8 分钟

**症状**：第一次访问美股，8 分钟才出数据
**根因**：`_load_us_codes()` 一次性下载 17636 条代码
**解决**：
- **正常现象**，不是 bug
- 后续秒级响应（代码列表已缓存）
- 如需加速：提前手动调一次 `get_us_json()` 预热

### 3.4 港股首次 2 分钟

**症状**：第一次访问港股，2 分钟才出数据
**根因**：AkShare `stock_hk_spot()` 冷启动
**解决**：
- V1.6.0.1 改为腾讯为主源，首启时间降到 5s
- 如仍慢：手动调一次 `get_hk_json()` 预热

## 4. 部署问题

### 4.1 Nginx 502 Bad Gateway

**症状**：浏览器打开 `https://oldcat.site` 502
**根因**：Nginx 转发到 8001 但 Uvicorn 没起
**诊断**：
```bash
sudo systemctl status marketview
sudo journalctl -u marketview -n 20
curl -s http://127.0.0.1:8001/api/health
```
**解决**：根据上面结果决定启动/重启后端

### 4.2 端口冲突

**症状**：`bind: address already in use`
**诊断**：
```bash
sudo lsof -i :8001
```
**解决**：杀掉占用进程或改端口（同步改 Nginx + systemd）

### 4.3 SSL 证书过期

**症状**：浏览器显示"您的连接不是私密连接"
**诊断**：
```bash
sudo certbot certificates
```
**解决**：
```bash
sudo certbot renew
sudo systemctl reload nginx
```

### 4.4 systemd 启动失败

**症状**：`systemctl start marketview` 失败
**诊断**：
```bash
sudo journalctl -u marketview -n 30 --no-pager
sudo systemctl show marketview | grep ExecStart
```
**常见根因**：
- `WorkingDirectory` 路径错
- `ExecStart` 虚拟环境路径错
- 用户权限（`User=www-data` 但文件属主是 `root`）

## 5. 模块专项

### 5.1 A股加载慢（51s）

**症状**：首次加载 A股 51 秒
**根因**（V1.4.2 之前）：串行拉取
**解决**：改并发
```python
# 11 个分片并发（每分片 500 只）
async with httpx.AsyncClient() as client:
    tasks = [client.get(url) for url in urls]
    responses = await asyncio.gather(*tasks)
```
**当前状态**：✅ 已修，A股首启 63ms

### 5.2 美股字段错位

**症状**：美股表格字段名错乱
**根因**（V1.6.0 之前）：东财 vs 腾讯字段名不同
**解决**：
- 改用腾讯源（V1.6.0）
- `_from_tencent_threaded` 拼接时加 `us` 前缀
```python
url = 'https://qt.gtimg.cn/q=' + ','.join('us' + c for c in batch)
```

### 5.3 港股 0 行（RemoteDisconnected）

**症状**：港股表格 0 条
**根因**（V1.6.0.1 之前）：单一 AkShare 源不稳
**解决**：多源 fallback
```python
def get_hk_json():
    for source in ['tencent', 'eastmoney', 'sina']:
        try:
            data = fetch_from(source)
            if data: return json.dumps(data)
        except Exception as e:
            print(f'[hk] {source}: {e}')
    return '[]'
```

### 5.4 加密货币显示"需代理"

**症状**：crypto 卡片显示 🔒 需代理
**根因**：服务器无 `CRYPTO_PROXY` 环境变量
**解决**：在 systemd 单元加
```ini
Environment=CRYPTO_PROXY=http://127.0.0.1:7897
sudo systemctl daemon-reload && sudo systemctl restart marketview
```

### 5.5 指数 global 为空

**症状**：`/api/index/spot` 返回 `global: []`
**根因**：东财 `index_global_spot_em` 需海外网络，限流
**解决**：
- **接受空值**（V1.6.0 决策）
- 客户端隐藏 global 区域或显示"暂无数据"
- 不要阻塞 china

### 5.6 K线指标算错（V1.7.0+）

**症状**：MA/BOLL/MACD 数值异常
**根因**：纯 Python 公式写错
**诊断**：
```bash
# 对账测试
curl -s 'https://oldcat.site/api/kline/stock/sh600519?period=1d&count=10' | python -m json.tool
# 手动算 MA5 = sum(c[-5:])/5，对比 ma.MA5[-1]
```
**解决**：
- EMA 公式：`α = 2/(N+1)`，`EMA[i] = close*α + EMA[i-1]*(1-α)`，`EMA[0] = close[0]`
- STDEV 用样本标准差（n-1 分母）
- HIST 在前 26+9-1=34 根都是 null

### 5.6.1 港股 K线 0 行（V1.7.0 Step 1 教训）

**症状**：`/api/kline/hk/hk00700` 返回 `data: []`
**根因**：单一腾讯 hkfqkline 主源 502 / RemoteDisconnected 后无 fallback
**诊断**：
```bash
curl -s 'http://localhost:8000/api/kline/hk/hk00700?period=1d&count=10' | python -c "import sys,json; d=json.load(sys.stdin); print(len(d.get('data',[])),'rows')"
# 预期 > 0；0 行 = fallback 链全部失败
```
**解决**：V1.7.0 Step 2 加 3 源 fallback（tencent hkfqkline → 东财 stock_hk_hist → 新浪 stock_hk_spot）。服务日志搜 `[kline_hk]` 看哪个源失败。

## 6. 性能问题

### 6.1 首屏加载慢

**症状**：打开页面，进度条卡在某个百分比
**诊断**：
```bash
# 看哪个模块慢
sudo journalctl -u marketview -n 100 | grep "Preload"
# 预期：[Preload] us OK (17209 → 11 shards)
```
**根因**：US 首次 8 分钟（正常）
**解决**：等，或手动预热

### 6.2 SSE 延迟

**症状**：浏览器看到数据有 5~10s 延迟
**根因**：Nginx 缓冲
**解决**：见 1.1

### 6.3 CPU 占用高

**症状**：`top` 显示 uvicorn 进程 CPU > 50%
**诊断**：
```bash
# 看 roller 频率
sudo journalctl -u marketview -n 200 | grep "shard"
```
**根因**：shard interval 太短（stock=1s，60s 拉 60 次）
**解决**：调整 `SHARD_CFG` interval

## 7. 常见误判

| 误判 | 真相 |
|------|------|
| "服务挂了" | 看 `systemctl status`，往往没挂 |
| "SSE 路由不存在" | 看 OpenAPI：`curl /openapi.json \| grep stream` |
| "数据源都返回 0" | 看是单模块还是全部，区分 fetcher 还是路由 |
| "腾讯源坏了" | 大概率是限流，等 5 分钟 |
| "viewTime 不准" | V1.6.0.8 起 viewTime 是客户端实时时间（每秒跳），V1.6.0.14 移出 if(tab)，V1.6.0.16 删 openModule 数据时间赋值，4 场景全覆盖（首页/切模块/数据静止/红点+老数据）|
| "验收脚本崩溃 UnicodeEncodeError" | Windows GBK 不支持 emoji，V1.6.0.15 加 `sys.stdout.reconfigure(encoding='utf-8', errors='replace')` 即可 |
| "ECharts K线图渲染空白" | 3 检查：① 容器 `#kline-chart` 是否有尺寸（`min-height:500px` + `flex:1`）② 父级 `#kline-view` 是否 `display:block`（非 `none`）③ `echarts.init(dom)` 是否在 `display:none` 时调用（必须可见时才 init，V1.7.0 Step 3 用 show() 中延迟 init）|
| "K线图 resize 失效/变形" | V1.7.0 Step 3 策略：hide() 时 `chart.dispose(); chart=null`，show() 时重建实例（`!chart → init()`）。每次切回都是新 chart，自动适配当前容器尺寸 |
| "MACD 切换后图表不更新" | 必须用 `chart.setOption(opt, {notMerge: true})`（grid/xAxis/yAxis 数量变化时 merge 模式会失败）|
| "分时图昨收虚线不显示" | 昨收由并行 1d(count=2) 请求的倒数第二根 close 提供。获取失败（网络/API异常）→ 静默降级，不显示 markLine 和昨收参考线，不影响分时图主渲染 |

## 8. 教训沉淀（必读）

| 版本 | 教训 |
|------|------|
| V1.6.0.1 | 缓存 schema 必须统一（写 `shards` 读 `shards`，不允许 `data`）|
| V1.6.0.1 | 多源 fallback 必备（HK 单一源 0 行教训）|
| V1.6.0.1 | `except: pass` 是禁忌，必须 print |
| V1.6.0.3 | viewTime 独立于 SSE 推送（不要嵌套 if(changed)）|
| V1.6.0.5 | ST 重建必带 fetchTime（doSort/openModule/goPage）|
| V1.6.0.6 | 后端不推空分片是设计缺陷，必须有独立心跳 |
| V1.6.0 | 美股腾讯源必须 `us` 前缀，否则返空 |
| V1.4.0 | SSE 路由 workers=1 铁律，>1 会路由错乱 |
| V1.7.0 | ECharts 容器必须在可见时 init（display:none 时尺寸为 0→空白）|
| V1.7.0 | ECharts grid/xAxis/yAxis 数量变化必须 notMerge（toggle MACD 时 grid 2→3）|
| V1.7.0 | dispose+重建比 resize 更可靠（切换视图后容器尺寸变化，resize 偶尔失效）|
