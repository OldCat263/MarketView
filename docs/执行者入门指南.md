## 4. 铁律（每次改动前必对照）

| # | 铁律 | 自检命令 |
|---|------|----------|
| 1 | **核心文件不变** | `git diff --stat backend/main.py frontend/js/core.js frontend/index.html` |
| 2 | **先改 CLAUDE.md 再写代码** | 实施前确认设计稿已含 CLAUDE.md 改动方案 |
| 3 | **服务端缓存允许，数据源必须公开 API** | 缓存可用但数据必须来自免费公开 API，`grep -rn "open(\|write(\|dump(" backend/` 不应有本地文件主数据源 |
| 4 | **数据源仅限免费公开 API** | 确认新数据源在免费清单（腾讯/东财/新浪/Binance/AkShare）|
| 5 | **做完记录版本历史** | 回报时附 V<x.y.z> + 一句话总结 |
| 6 | **每个模块完全独立封装** | `git diff` 应只触及本模块文件，不跨模块 |
| 7 | **改代码必同步技术文档** | 按 [§0.1 分工表](#01-文档改动分工表必背) 跑一遍检查 |
| 8 | **设计师必审批技术文档** | 回报里附设计师"§7.1 技术文档同步 4 检查点"全过 |

> 来源：[开发手册 §二](./开发手册.md)。**每改一处先过这 8 条**。

## 5. 协作流程（你在哪一步）

```
1. 用户提需求
2. 设计师：出设计稿 + 更新本指南 §0 + 开发手册 + CLAUDE.md
3. 设计师：出实施指令（5 步分开发推荐）→ 发给用户
4. 用户：转发给你
5. ⭐ 你：读设计稿 → 对照铁律 → 写代码 → 同步技术文档 → 跑验收 → 按 §7 回报
6. 设计师：3 项验收（代码 + 技术文档 + 标级）
7. ⭐ 审批员：复审设计师的验收（按 [审批员入门指南 §6](./审批员入门指南.md)）
   7.1 跑 §6 复审清单（10 项 + 4/5 类实测）
   7.2 按 §7 重标级（可与设计师不同）
   7.3 按 §9 出改进意见
8. 审批员发回设计师
9. 设计师：按审批员意见改完 → 审批通过 → CLAUDE.md 加版本号 → 封版
10. ⭐ 失败回滚：复审 P0 打回 → `git revert <hash>` → 重新走流程
```

> 详细见 [开发手册 §十](./开发手册.md) + [设计师入门指南 §5](./设计师入门指南.md) + [审批员入门指南 §5](./审批员入门指南.md)。

### 5.1 5 步分开发的协作策略
当设计师出"5 步分开发"指令（如 V1.7.0）时，按"轻量验收 + 完整复审"分层：
| 阶段 | 流程 | 你的责任 |
|------|------|----------|
| Step 1~4 | 走"实施 → 回报 → 设计师轻量验收"（不经过审批员）| 你按 §7 完整回报，设计师重点审"模块独立 + 文档同步" |
| Step 5 | 走"实施 → 回报 → 设计师验收 → 审批员完整复审 → 封版" | 全员（接口/UI/SSE 完整联调）|

> **理由**：避免 5×3=15 次完整流程拖进度；Step 5 必走完整（UI/接口/SSE 联调 P0 高发）。
> **风险**：Step 1~4 漏掉的 P0 要 Step 5 才能发现。

## 8. 验收清单（执行者必跑）

### 后端验收

```bash
# 1. 启动检查（必须无 traceback）
cd backend && uvicorn main:app --workers 1
# 预期：6 个 roller + 6 个 heartbeat 全部 OK，无 FAIL

# 2. 逐模块数据量
for m in stock etf hk us index crypto; do
  curl -s http://localhost:8000/api/$m/spot | python -c "import sys,json; d=json.load(sys.stdin)['data']; print('$m:', len(d) if isinstance(d,list) else 'dict')"
done

# 3. SSE 心跳
curl -N -m 6 http://localhost:8000/api/stream/stock | grep -c 'shard.-1'
# 预期：1~2（6s 内 3s 一次）
```

### 前端验收

| # | 检查项 | 通过标准 |
|---|--------|----------|
| 1 | 8 张卡片全部加载 | 无 -- 占位，全部数字 |
| 2 | F12 EventStream | `/api/stream/{m}` 持续收 data: 行 |
| 3 | 切模块不串台 | 搜索/排序/翻页各模块独立 |
| 4 | viewTime 不变红 | 持续显示时间，绿点 |

## 9. Commit 规范

```
<hash> V<version>: <一句话总结>
```

例：
```

a3b2c1d V1.6.0.5: ST rebuild preserve fetchTime
```

**规则**：
- 一句话总结 ≤ 30 字
- 动词开头（add / fix / refactor / optimize）
- 涉及多文件用 `+`：`V1.7.0: kline module + ECharts frontend`
